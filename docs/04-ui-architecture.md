# Megu3D — UI-архитектура

Версия 0.1 · 2026-08-13 · draft M0
Связанное: [assumptions](./assumptions.md) · [PRD](./01-prd.md) · [architecture](./02-architecture.md) · [roadmap](./03-roadmap.md)

## 1. Принципы «UI без каши»

1. Контекст важнее полноты: показываются только панели и параметры, релевантные текущему workspace, режиму и выделению.
2. Одна панель — одна ответственность. Панель, которая делает две вещи, делится на две.
3. Прогрессивное раскрытие: базовые параметры видны, advanced — в свёрнутой секции «Дополнительно».
4. Любая команда достижима тремя путями: палитра, меню, хоткей. Мышь никогда не обязательна.
5. Плотность профессиональная, но дышащая: сетка 4 px, компактная типографика, без декоративного шума.
6. Никаких модальных окон там, где хватит инлайн-панели или дока.
7. Состояние сцены не живёт в React: панели — проекции ядра.

## 2. Каркас окна

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ Titlebar: меню · workspace switcher · поиск/палитра · статус проекта      │
├───────┬───────────────────────────────────────────────┬───────────────────┤
│ Tools │                                               │ Outliner          │
│ (лево)│              Viewport / Editor                ├───────────────────┤
│       │                  (центр)                      │ Properties        │
│       │                                               │ (право)           │
├───────┴───────────────────────────────────────────────┴───────────────────┤
│ Timeline / Graph / VSE — по контексту workspace                            │
├───────────────────────────────────────────────────────────────────────────┤
│ Statusbar: режим · выделение · подсказка операции · FPS · прогресс задач   │
└───────────────────────────────────────────────────────────────────────────┘
```

Правила: центр всегда занимает максимум; правая колонка — стек Outliner (сверху) и Properties; нижняя зона появляется только там, где нужна по контексту; левая полоса инструментов зависит от режима.

## 4. Модель докинга

```ts
type LayoutNode =
  | { kind: "split"; dir: "row" | "col"; sizes: number[]; children: LayoutNode[] }
  | { kind: "tabs"; active: number; panels: PanelId[] }
  | { kind: "panel"; id: PanelId }
```

- Реализация своя (без тяжёлой зависимости): CSS grid/flex + pointer events, ресайз по сплиттерам, перетаскивание панелей в табы или в новую область.
- Layout сохраняется на workspace в `layout.json` профиля пользователя; версионируется вместе с настройками.
- «Reset layout» возвращает пресет workspace, не задевая остальных.
- Viewport — не React-дерево: это native surface под областью панели. React рисует только рамку, оверлеи и HUD.

## 5. Система команд и хоткеев

```ts
type Command = {
  id: string                  // "object.add.cube", "edit.undo", "view.frameSelected"
  title: MessageKey           // локализуемый заголовок
  category: MessageKey
  when?: ContextPredicate     // режим, workspace, наличие выделения
  run: (ctx: CommandContext) => Promise<void>   // dispatch intent в ядро
}
```

- Единый реестр: палитра, меню, хоткеи и панели читают один и тот же список. Дублирования логики нет.
- Палитра: fuzzy-поиск по названию, категории и синонимам; показывает хоткей и недавние; ищет и по настройкам, и (с P1) по ассетам.
- Keymap слоями: `default` → `preset` (например, «привычная схема») → `user`. Конфликты показываются явно.
- Все хоткеи переназначаемы; поиск по хоткею («что делает Alt+E») поддерживается.
- Хоткеи независимы от языка интерфейса: привязка по физической клавише (`KeyE`), а не по символу.

## 6. Состояние UI

| Тип состояния | Где живёт | Пример |
|---|---|---|
| Состояние сцены | Rust-ядро | ноды, трансформы, материалы |
| Проекция сцены (view-модель) | стор UI, обновляется патчами | дерево outliner, свойства выбранного |
| UI-состояние | стор UI, персистентно | layout, активный workspace, свёрнутые секции |
| Эфемерное | локальный state компонента | наведение, открытое меню, черновик поля ввода |

Правила: панели подписываются на срезы, а не на весь стор; списки виртуализированы (Outliner на 100k+ строк); ввод в числовых полях коммитится по `Enter`/`blur`, а drag-скраб идёт через preview-транзакцию.

## 7. Дизайн-токены и темы

```css
:root[data-theme="dark"] {
  --mg-bg-0: #16181c;   /* фон приложения */
  --mg-bg-1: #1d2025;   /* панель */
  --mg-bg-2: #24282e;   /* поле, вложенная секция */
  --mg-bg-3: #2d323a;   /* hover */
  --mg-line: #363c45;
  --mg-text-0: #e6e9ee;
  --mg-text-1: #a7b0bd;  /* второстепенный */
  --mg-accent: #4c8dff;
  --mg-warn: #f0a13c;
  --mg-danger: #e2564f;
  --mg-ok: #46c07a;
  --mg-radius: 6px;
  --mg-space: 4px;       /* базовый шаг сетки */
  --mg-font-ui: "Inter", "Segoe UI", system-ui, sans-serif;
  --mg-font-mono: "Cascadia Mono", "Consolas", monospace;
  --mg-text-size: 13px;
}
```

- Тёмная тема — основная, светлая — полноценный вариант на тех же токенах. Никаких цветов вне токенов.
- Оси в UI окрашены единообразно: X красный, Y зелёный, Z синий — те же цвета в гизмо, полях трансформа и графах.
- Информация никогда не передаётся только цветом: добавляются иконка, форма или подпись.
- HiDPI: всё в логических пикселях, иконки — SVG, viewport рендерится в физическом разрешении с `devicePixelRatio`.

## 8. Взаимодействие в viewport

| Действие | Ввод по умолчанию |
|---|---|
| Орбита | средняя кнопка мыши |
| Пан | Shift + средняя кнопка |
| Зум | колесо / Ctrl + средняя |
| Frame selected | `.` (numpad) или `F` |
| Выделение | ЛКМ; Shift — добавить, Ctrl — исключить, drag — box-select |
| Move / Rotate / Scale | `G` / `R` / `S`, ось уточняется `X`/`Y`/`Z`, значение вводится с клавиатуры |
| Отмена операции | `Esc` — abort транзакции, состояние возвращается точно |
| Переключение режима | `Tab` (Object ↔ Edit) |

Правила: во время модальной операции статусбар показывает подсказку и текущее численное значение; гизмо не перехватывает клики за своими пределами; любое перетаскивание можно прервать `Esc` без остатков в истории.

## 9. Локализация

- `packages/i18n`, ICU-сообщения, ключи вида `panel.outliner.title`, `cmd.object.add.cube`.
- RU по умолчанию при системной локали `ru-*`, иначе EN; переключение без перезапуска.
- Правила: ни одной строки в компонентах; числа, даты и единицы форматируются через locale-aware форматтеры; тексты ошибок локализуются по коду ошибки из ядра.
- Проверка в CI: скрипт ищет литеральные строки в JSX и отсутствующие ключи переводов.

## 10. Доступность

Полная клавиатурная навигация, включая доки и палитру · видимый фокус на всех интерактивных элементах · ARIA-роли для панелей, табов, меню, деревьев · контраст текста ≥ 4.5:1 · масштаб UI 80–200% без обрезаний · уважение `prefers-reduced-motion` (анимации ≤ 150 ms, отключаемы) · тултипы не единственный носитель смысла.

## 11. Инвентарь панелей (M2–M4)

| Панель | Ответственность | Этап |
|---|---|---|
| Viewport | native-рендер, гизмо, оверлеи, HUD | M2 (заглушка) → M3 |
| Outliner | иерархия, выбор, видимость, блокировка, drag-parent | M3 |
| Properties | контекстные свойства объекта/данных/материала/света | M3 → M4 |
| Tools | инструменты активного режима | M3 |
| Command palette | поиск и запуск команд и настроек | M2 |
| Statusbar | режим, выделение, подсказка операции, FPS, прогресс | M2 |
| Modifiers | стек модификаторов | M5 |
| Timeline | кадры, ключи, воспроизведение | M7 |
| Preferences | настройки по страницам с поиском | M2 → M4 |
| Notifications | уведомления, ошибки, «Copy diagnostics» | M4 |

## 12. Чек-лист качества панели

Перед мержем панели: одна ответственность · полностью локализована · работает с клавиатуры · пустое, загрузочное и ошибочное состояния оформлены · advanced скрыт по умолчанию · все действия зарегистрированы как команды · список виртуализирован при неограниченной длине · подписка на срез стора, а не на весь стор · корректна при 200% масштабе и в светлой теме.
