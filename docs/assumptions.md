# Megu3D — Принятые допущения

Версия 0.1 · 2026-08-13 · живой документ.
Правило: допущение действует, пока владелец продукта его явно не отменил.
`D-*` — решение, принятое как профессиональный default. `A-*` — допущение, стоит подтвердить.

## 1. Продукт

| ID | Решение | Цена отмены |
|---|---|---|
| D-01 | Имя продукта — Megu3D | ребрендинг: пакеты, crate, bundle id, docs |
| D-02 | Desktop DCC полного цикла (создание, не просмотр) | смена всей архитектуры |
| A-03 | Аудитория: инди-3D-артисты, дизайнеры, small studio | смена приоритетов P1/P2 |
| A-04 | v1 — standalone, без облака и аккаунтов | добавляются auth, backend, биллинг |
| D-05 | UI: RU + EN, RU по умолчанию при системной локали `ru-*` | меняется только набор локалей |

## 11. Ядро сцены (M3)

| ID | Решение | Цена отмены |
|---|---|---|
| D-80 | Математика (Vec3/Quat/Mat4/AABB) написана вручную в `megu3d-core`, без `glam` | замена типов в ядре и пересборка матриц (1–2 дня) |
| D-81 | Новый документ не пуст: Camera + Sun + Cube, куб выделен | один вызов `Scene::new()` вместо `Scene::startup()` |
| D-82 | Выделение не попадает в undo-историю (как в Blender/Maya) | добавляется команда `SelectNodes`, история шумит |
| D-83 | Дубликат делит mesh-данные с источником (instancing по умолчанию) | в M5 появляется copy-on-write при входе в Edit Mode |
| D-84 | Каждый dispatch возвращает полный снимок сцены + patch с изменёнными узлами | инкрементальные патчи включаются при >10k узлов (M4–M5) |
| A-85 | Mesh-данные удалённых узлов не собираются GC до M4 (нужны для undo) | asset-GC при сохранении и обрезке истории |
| D-86 | Вьюпорт M3.2 — превью на Canvas 2D: сетка, мировые AABB каркасом, маркеры начал координат и gizmo; затенённых мешей нет — буферы геометрии не входят в снимок сцены | wgpu-рендер заменяет только слой отрисовки, слой ввода остаётся (M4) |
| D-87 | Move-gizmo точен: мировая дельта переводится в пространство родителя через обратную линейную часть; Rotate/Scale правят локальные эйлеры и масштаб узла | мировой кватернионный gizmo вместе с GPU-рендером (2–3 дня) |
| D-88 | Пикинг — CPU в экранном пространстве: сначала ближайший маркер начала координат в радиусе, иначе наименьший охватывающий AABB | GPU id-buffer после рендерера (1–2 дня) |
| D-89 | Интерактивные правки шлют preview-команды с троттлингом по requestAnimationFrame; pointerup → commitPreview (одна запись в undo), Escape → cancelPreview | переход на предсказание в ядре при сетевом/многопоточном режиме |
| D-90 | Горячие клавиши в духе Blender: G/R/S, Shift+A, X и Delete, Shift+D, Alt+A, F; кеймап игнорирует поля ввода | редактор горячих клавиш и пресеты чужих DCC (M4+) |
| A-91 | Outliner рисует список целиком, без виртуализации; допущение — до ~2000 узлов без просадки | виртуальный список в M5 (полдня) |
| A-92 | Зеркалирование в GitHub идёт пофайлово через Contents API: `git/trees` и `.github/workflows/*` отвечают 403 | fine-grained PAT со скоупами Contents: RW + Workflows: RW возвращает пакетный push |
| D-93 | На GitHub история линейная, «файл = коммит»; подлинные ветки M0–M3 остаются в локальном `.git` | `git push --force` с машины владельца переносит настоящую историю |
| D-94 | `Cargo.toml` поле `repository` указывает на `github.com/sashavladimirovich2006-pixel/Megu3Des` | правка одной строки при переезде репозитория |

## 12. Ввод-вывод проекта (M4)

| ID | Решение | Цена отмены |
|---|---|---|
| D-95 | ZIP-контейнер `.megu3d` читается и пишется своим минимальным кодеком (метод `stored`, CRC-32 вручную), без сторонних крейтов сжатия | переход на `zip`/`zstd` — полдня, набор entries не меняется |
| A-96 | Сцена хранится как `scene.json` — конверт `{ schemaVersion, units, scene }` в pretty-JSON; `scene.bin` появится после ADR-2 | файл в ~3 раза крупнее бинарного, зато диффится в git |
| D-97 | Байты контейнера детерминированы: время записей зафиксировано на 1980-01-01, порядок entries — manifest → scene | штатное время файла в проводнике вернётся вместе с настоящим кодеком |
| D-98 | Миграции идут по `serde_json::Value` до типизации, цепочкой шагов «версия → следующая»; файл новее сборки отклоняется | по одному шагу на каждую версию схемы, старые шаги не переписываются |
| D-99 | Сохранение атомарно: временный файл рядом с целью → `sync_all` → старый файл в `*.bak` → rename | требует одной файловой системы для цели и временного файла |
| A-100 | Коды ошибок `IO_CONTAINER_INVALID`, `IO_JSON_INVALID`, `IO_ENTRY_MISSING`, `IO_SCHEMA_TOO_NEW`, `IO_SCHEMA_UNSUPPORTED`, `IO_FS_FAILED` — часть контракта с UI | переименование кода требует правки i18n-ключей |
| A-101 | `assets/` и `thumbnail.png` зарезервированы в манифесте, но не пишутся до импорта текстур (M6) | `thumbnail` объявлен как необязательное поле, схема не ломается |
