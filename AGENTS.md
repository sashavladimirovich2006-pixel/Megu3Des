# AGENTS.md — правила работы агентов в репозитории Megu3D

**Сначала прочитай `docs/HANDOFF.md`.** Там полный контекст проекта: статус, решения, что работает, что сломано и точный следующий шаг. Этот файл — только о том, **как** работать.

## 1. Обязательный порядок действий

1. Проверить состояние: `cd /data/megu3d && git log --oneline -3 && git status --porcelain && python3 tools/gate.py`.
2. Сделать один логический этап (не больше).
3. Перед коммитом: `git add -A && python3 tools/gate.py` — гейт перечисляет файлы через `git ls-files`, поэтому без `git add` он не увидит новые файлы.
4. Коммит кода, затем отдельный коммит решений в `docs/assumptions.md`.
5. После этапа — собрать архив репозитория и отдать пользователю (страховка от отката песочницы).
6. Ответ пользователю — по шаблону из раздела 7.

## 2. Гейт — единственная автопроверка без сети

`python3 tools/gate.py` проверяет: завершающий перевод строки; запрет `any`/`as any` в TS; баланс скобок; паритет и порядок ключей i18n в `packages/i18n/src/messages/{en,ru}.ts`; использование ключей в UI; полноту `CommandContext`/`PanelContext` относительно `AppShell.tsx`; дубли горячих клавиш; соответствие IPC между `packages/ipc/src/index.ts`, `ipc.rs` и `main.rs`.

Вывод вида `ipc=13 bindings=30 keys=133/133 usedKeys=117` и `PROBLEMS: none`. Любая проблема — выход 1 и запрет на коммит. Гейт — НЕ замена `cargo`/`tsc`/`vitest`; не выдавай его за тесты.

Если добавляешь проверку в гейт — сначала убедись, что она видит реальные данные (когда-то проверка горячих клавиш тихо считала `bindings=0` и пропускала всё; исправлено в `966c0c8`).

## 3. Как править файлы в песочнице (проверенный метод)

- **Новые файлы** — целиком через запись файла; большие файлы делить на части с дозаписью (`append`). Не писать большие файлы heredoc'ами — они обрываются (`warning: here-document … delimited by end-of-file`).
- **Правки существующих файлов** — python-скрипт до 10 КБ в `/data/patch/`, через хелпер `/data/patch/patchlib.py` (`read/write/swap/drop/resub/after_line/insert_before_last/append`). Каждая правка — с точным ожидаемым числом совпадений и громким маркером в выводе; скрипт должен быть идемпотентным.
- **Проверка идемпотентности** — только по маркеру объявления (`**D-109.**`), не по голому идентификатору: ссылка в чужом абзаце даёт ложное срабатывание.
- **Одна цепочка команд на этап**: генерация вспомогательных файлов и текстов коммитов → патчи → `git add -A` → гейт → коммит → проверка. `/tmp` обнуляется между вызовами — всё временное держать в `/data/patch/`, тексты коммитов создавать в том же вызове, в котором коммитишь.
- **Проверка результата — по байтам и строкам** (`wc -c`, `wc -l`, баланс скобок), а не глазами: вывод терминала искажает кириллицу.
- **JSON-аргументы**: кириллица работает как литеральный UTF-8 в записи файла и как `\uXXXX` внутри `<<'EOF'`. Внимательно экранируй `\"` и `\\`; вместо байтовых литералов вида `b"BIN\0"` используй шестнадцатиричные константы.

## 4. Стиль кода

- Rust: 4 пробела, `snake_case`/`PascalCase`, `thiserror`, у каждой ошибки `code()` и `recoverable()`. `CmdError` и `InteropError` выводят `PartialEq` — внутрь нельзя класть `std::io::Error`, только строки/коды.
- TypeScript: табуляция, без `any`, без `!`, без пустых `catch {}`, `verbatimModuleSyntax`, `noUncheckedIndexedAccess`. Компоненты — `PascalCase.tsx`, тесты — `*.test.ts` рядом с кодом.
- JSON — 2 пробела. Все текстовые файлы заканчиваются переводом строки.
- Имена IPC, ключей i18n, команд и веток — по разделу 3.6 `docs/HANDOFF.md`.
- Новые решения — в `docs/assumptions.md` тем же ходом, что и код, ссылающийся на них. Следующий свободный идентификатор: **`D-123`**.

## 5. Запрещено

- Превращать UI в кашу и собирать монолит вместо крейтов/пакетов.
- Ломать undo/redo, сохранение и обмен геометрией без миграции.
- Секреты, токены и локальные пути пользователя в коде, коммитах и логах.
- Заявлять, что что-то «работает» или «тесты прошли», если сборка и тесты не запускались.
- Задавать вопросы по мелочам: выбирать разумный дефолт, записывать его как допущение и идти дальше.

## 6. Ограничения песочницы

- Сети нет: `pnpm`, `cargo`, `go`, `tsc`, `vitest`, `git push` недоступны. Есть `python3`, `node`, `zip`/`unzip`, `git` локально.
- Песочница может откатиться вместе с историей git (было три раза). Лечение: архивы после каждого этапа и `git fsck --lost-found` + `git show <sha>:<path> > <path>`.
- Зеркало GitHub обновляется только поштучно через Contents API и стоит примерно два размера файла в токенах; Trees API и `.github/workflows/*` отдают 403. Быстрый путь — отдать архив и пуш с машины пользователя.
- Подпись коммитов агента: `git -c user.name='Megu3D Bot' -c user.email='dev@megu3d.local' commit …`.

## 7. Формат ответа пользователю (русский, 8 разделов)

1. Понимание задачи · 2. Принятые допущения · 3. План · 4. Код/файлы/конфиги · 5. Команды · 6. Тесты/проверка · 7. Риски · 8. Следующий шаг.

Если ответ не вмещается — закончить фразой «Продолжить следующую часть». В разделе 7 обязательно повторять, что код не компилировался и тесты не запускались, пока это так.
